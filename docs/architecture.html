01整体系统架构

最上层是用户通过浏览器访问。前端是 Vue3 单页应用，由 nginx 在同一容器内托管静态文件，并把 /api 请求同源反代到后端（免 CORS）。后端 FastAPI 负责业务编排，持久化数据落在 PostgreSQL（小说/用户/章节等结构化数据），检索增强（RAG）数据落在 Chroma 向量库，创作能力依赖智谱 GLM（通过 OpenAI 兼容协议调用）。整套服务跑在腾讯云轻量服务器的一个 Docker Compose 里。

02前端技术栈与结构

前端基于 Vue3 + Pinia + Vue Router + Element Plus + axios。路由分三层：登录/注册页、小说列表页、小说工作台。工作台内聚了大纲 / 世界观 / 角色 / 章节 / 记忆伏笔五个创作视图，所有网络请求统一走 api.js（axios 实例 + 响应拦截器做中文友好报错）。登录态 token 由 pinia 持久化，「模型设置」弹窗供用户配置个人专属模型 Key（仅自己生效）。

03后端模块结构

后端以 FastAPI 组织：main.py 在启动时建表并加载全局运行配置；四个路由模块分别负责鉴权、小说业务、RAG 查询、模型设置。所有重活都经由 Coordinator 编排，它调度 6 个 Agent 完成创作，底层依赖 core（LLM 客户端与运行时配置解析）和 memory_manager（同时封装 PostgreSQL 结构化存储与 Chroma 向量存储）。数据库表结构由 models/db.py 用 SQLAlchemy Core 定义。

04鉴权与数据隔离原理（B 方案）

采用「独立账号 + 数据隔离」方案（B 方案）。注册时密码经 bcrypt 哈希存入 users 表；登录校验后签发有效期 30 天的 JWT（HS256）。此后每个业务请求在 Header 携带 Bearer Token，后端 require_user 依赖统一解析出用户身份。所有小说相关查询都强制按 owner_id 过滤，任何用户只能看到和操作自己的数据——这是行级隔离，外人即便知道 ID 也会拿到 404。

05多 Agent 协作全景

6 个 Agent 围绕 Coordinator 协作，分两条流水线：
• 创建流水线（一键成书）：WorldBuilder 出世界观 → PlotArchitect Pass-1 出大纲骨架 → CharacterDesigner 出人设卡 → PlotArchitect Pass-2 细化大纲（大纲跟随角色）。
• 写作流水线（逐章）：ChapterWriter 写草稿 → ConflictEditor 做四维评分，不达标（<24/40）则把意见回灌重写（≤2 次） → 定稿后 MemoryKeeper 更新角色状态、埋设/回收伏笔。

06一键成书流水线原理

「一键成书」由 Coordinator.create_book_pipeline 同步串行执行 4 次大模型调用：① WorldBuilder 生成世界观并写入 RAG；② PlotArchitect Pass-1 产出大纲骨架；③ CharacterDesigner 依据大纲+世界观产出人设卡；④ PlotArchitect Pass-2 消费人设卡细化大纲。每步之间 sleep(3s) 缓冲，避免突发请求撞智谱 429 限流。整段在单个 HTTP 请求内同步完成，因此前端设了 600s 超时。（这也是当前瓶颈：串行 + 大模型慢，治本方案是改异步任务 + 进度轮询。）

07单章生成流水线原理

逐章写作流水线：先构建章节上下文并做 RAG 检索，ChapterWriter 据此写出草稿；ConflictEditor 对草稿做四维评分（满分 40），总分 ≥24 视为达标，否则把审校意见回灌给 ChapterWriter 重写（最多 2 次）。达标后章节落库并写入 RAG（供后续章节跨章召回），最后 MemoryKeeper 更新角色状态、埋设或回收伏笔，形成长线一致性。

08RAG 检索增强原理

RAG（检索增强生成）分两阶段：写入时，世界观条目与章节正文经嵌入模型转成向量，分别存入 Chroma 的 world / chapter 两个集合；读取时，章节生成前调用 retrieve_for_generation 从两个集合召回最相关上下文，拼进 Prompt，让模型「记得」前文设定与剧情，减少人设崩坏和设定矛盾。

09每用户模型 Key 隔离原理

为避免「一人填错 Key 炸全站」，模型调用走 resolve_user_settings 解析：优先使用用户个人在「模型设置」里填的 Key 与模型（存于 users.model_settings_json，仅自己生效）；若未填，则回落到站点级兜底 Key（来自 .env 的 ZHIPU_API_KEY）。解析结果注入 LLMClient，因此 A 用户填错只影响 A 自己，不会波及他人。

10生产部署架构

生产部署是单台腾讯云轻量服务器上的 Docker Compose 全家桶：postgres（PostgreSQL，pgdata 卷持久化）、backend（FastAPI）、frontend（nginx 托管前端并反代 /api）。Chroma 向量数据落在 chroma_data 命名卷。所有服务设 restart: unless-stopped，服务器重启或容器异常会自动拉起，本地电脑关机不影响云端运行。更新代码只需在服务器执行 redeploy.sh（git pull + 重建镜像）。
